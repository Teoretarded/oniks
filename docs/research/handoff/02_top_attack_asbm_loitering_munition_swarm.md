# Spec 2: Top-attack ASBM + loitering-munition swarm

> Implementation-research spec for a fresh implementer. Read HANDOFF_README.md first for codebase orientation + non-negotiables.

## Summary
Two new PLAYER offensive systems that break the SM-2 screen on a different axis than the existing lo-lo Oniks: (A) a quasi-ballistic top-attack anti-ship missile that beats SAMs by ALTITUDE+SPEED (lofted arc, near-vertical MaRV dive) and (B) a loitering-munition swarm with coordinated time-on-target that beats point-defense by SATURATION. Both are implementable against the real codebase with HIGH reuse: the ASBM reuses sim/sam.py SamMissile's loft/dive/PN phase machine (already per-round loft via SamDef.loft_*) re-pointed at ships; the swarm reuses sim/missile.py Missile's route/Mach-hold/salvo-weave machine. Critically the SM-6 counter to a high ASBM ALREADY EXISTS (sim/enemy_defense.py _try_sm6_launch, SM6_AREA_MIN_ALT_M=1500 m area band) — so the ASBM slots cleanly into the established "go high and the SM-6 reaches you, go low and you're back in the multipath duel" loop. The ASBM's design tension is the long time-of-flight punishing STALE tracks (it flies on the contact estimate like the S-300 does, only the terminal seeker sees truth); the swarm's is per-round speed control (commanded_speed = path_length / arrival_time) so geographically dispersed rounds converge in the same second. Both honor the three non-negotiables: outcomes emerge from the existing physics (loft energy + multipath/seeker geometry + fuse-vs-truth; per-round drag-limited speed-hold + the existing CIWS/SM-2 in-flight caps), the enemy AI reads ONLY its sensor picture (the SM-6/SM-2/CIWS fire off the dead-reckoned ContactBoard tracks they already use), and all RNG is seeded child streams (the world-seed phase-tag pattern in world/combat.py). Real-world grounding: ASBM ~ DF-21D-class lofted MaRV (apogee tens of km, terminal Mach 8-10, fins-steered diving warhead); swarm ~ Switchblade-600/Lancet-class subsonic loiterers (40+ min endurance, ~40 km, coordinated simultaneous-arrival is a documented multi-munition technique — USPTO 11971731, arXiv 2303.16951).

**Dependencies:** PRE-EXISTING (no new work, must stay intact): (1) sim/sam.py SamMissile per-round loft (loft_gain/loft_bias_max/loft_fade_range on SamDef) + terminal PN + proximity-fuse-on-truth + multipath OU — the ASBM is a SamMissile subclass. (2) sim/enemy_defense.py SM-6 area channel (_try_sm6_launch, SM6_AREA_MIN_ALT_M=1500 m) — the ASBM's high-midcourse counter ALREADY EXISTS; ASBM must keep its midcourse above that band. (3) sim/missile.py Missile route + _sustainer_thrust Mach-hold + _acquire_lock terminal seeker + per-salvo weave — the swarm reuses all of it; the _commanded_speed edit must be guarded so unset = bit-identical (regression contract). (4) world/combat.py launch()/_oniks_tubes salvo battery + _contact_estimate dead-reckoning + the Pantsir-style destructible-Structure-with-magazine pattern (the SwarmPod copies it) + the seeded child-stream phase-tag RNG convention. (5) game/sandbox.py request_launch + cycle_oniks_weapon (B) + tactical_map target/waypoint flow + PLATFORMS_COMBAT TAB cycle + game/keybinds.py action table. (6) world/combat_config.py CombatConfig frozen schema + clamp_config (ADD asbm_ammo, n_swarm_pods/swarm_ammo/swarm_mag_reload_s fields + CLAMPs — schema change needs the documented integrator sign-off). CROSS-CLUSTER: both features feed the consolidated UI plan (weapon-selector/info-card for ASBM; the swarm tasking panel is a major new map surface) and the consolidated enemy-AI plan (the OPTIONAL commander tweaks — SM-6 prefer-highest-closing-rate; raise-radar-on-raid — should be merged with other AI-brain changes rather than landed piecemeal). The low-RCS swarm radar size class (optional) should be coordinated with any other radar-class table changes.

**Open questions:** 1) ASBM ammo + apogee/range exact numbers need a measured flyoff sweep (like tools/compare_s300_rounds.py) to lock 'apogee >= 40 km AND terminal dive steeper than -60 deg AND it stays SM-6-targetable in midcourse' — pick loft_bias_max + motor_time so the high-loft arc actually dives near-vertical at the SEA surface (the 40N6's 4 km floor and 45 km fade must NOT be copied; the ASBM dives to the deck). 2) Does the ASBM terminal MaRV seeker reacquire a ship the stale midcourse missed, or commit to the dead-reckoned point? (Design intent: short reacquire window so a fast mover on a stale track survives — the fresh-track requirement; confirm via the test_asbm_misses_fast_mover_on_stale_track contract.) 3) Swarm: is the bundle a single shared route with auto speed-sync (v1 spec) or per-round fan-out routes (each round its own ingress bearing)? Each Missile already owns a route, so fan-out is cheap — but the tasking UI must then let the player draw N routes. Recommend v1 = shared route + speed-sync, fan-out as fast-follow. 4) Swarm RCS: keep 'missile' size class (v1) or add a low-RCS class with shorter enemy-detect range (more realistic for small loiterers, bigger UI/radar-table change)? 5) Should the swarm pod be a separate destructible asset that, if killed, removes the option (consistent with the base-defense lose-pressure), or co-located with the Bastion? 6) Confirm the integrator sign-off path for the CombatConfig schema additions (LOCKED schema per world/combat_config.py docstring).

## Feature: Bastion-K quasi-ballistic top-attack ASBM (new trajectory regime; reuse SamMissile loft/dive machine re-pointed at ships)  _(effort: M)_

**What it is + real-world grounding:**

A lofted quasi-ballistic anti-ship missile that climbs to a high apogee, coasts, then dives near-vertically onto a ship from above — beating the SM-2 by altitude/speed geometry rather than the horizon (the lo-lo Oniks' trick). Grounded in the open DF-21D/DF-26 ASBM concept: a solid-boost MRBM-class round with a lofted ballistic profile (apogee in the tens of km) and a maneuvering reentry vehicle (MaRV) steered by fins onto a moving ship, terminal speed quoted at Mach 8-10 (https://www.missiledefenseadvocacy.org/missile-threat-and-proliferation/todays-missile-threat/china/dong-feng-21d-df-21d/ ; https://behorizon.org/df-21d-east-wind-the-worlds-first-asbm/ ; armscontrolwonk DF-21 Delta). Fictionalized as 'Bastion-K' so it is plausibly grounded, not a production copy. This is the THIRD attack axis (GAME_ANALYSIS §7 gap: 'no hypersonic/long-range anti-ship punch' — Zircon filled speed-on-a-flat-profile; this fills the over-the-top vertical axis with a hard fresh-track requirement).

**Platform (launched from / carried by):**

Player Bastion TEL battery (the existing self._oniks_tubes salvo battery in world/combat.py). Decision: it launches from the SAME Bastion tubes as Oniks/Zircon, selected by the existing B 'oniks_weapon' cycle (extend the 2-state oniks<->zircon toggle to 3-state oniks->zircon->asbm). Rationale: the round is anti-ship and the player already aims the Bastion at ship contacts; adding a 4th launcher type would bloat the TEL set. It draws from its OWN scarce ammo pool (config.asbm_ammo, like zircon_ammo). Enemy does NOT carry it (the enemy's over-the-top analog is the existing JASSM/TLAM ballistic-ish strike on the base; keeping ASBM player-only preserves the asymmetry the game is built on). Physically it is the SamMissile airframe family (cold/hot boost, loft, coast, dive) — NOT the ramjet Missile — so it carries a SamDef, but its TARGET is a ship contact, which is the novel wiring.

**Sensors (uses / detected by):**

USES: the player ContactBoard surface track of the target ship (drone SAR / ELINT / radar-net), exactly the picture the Oniks already needs — but the LONG time-of-flight (lofted 380+ km-class arc = ~120-300 s) means a track that was fresh at launch is badly stale at arrival, so the round flies BOOST/MIDCOURSE on a dead-reckoned contact_estimate_fn (the SamMissile already supports this) and only the terminal MaRV seeker (a downward-looking active radar, modeled as the SamMissile own-seeker terminal PN with illuminator_pos_fn=None like the 40N6 ARH) sees truth. DETECTED BY: the enemy SPY-1/AWACS/SM-6 fire control as a HIGH inbound missile track — it spends its whole midcourse far above SM6_AREA_MIN_ALT_M (1500 m), so it is squarely in the SM-6 area-defense band, plus a clean (non-multipath) track because it is high. The terminal vertical dive is the window where it drops THROUGH the SM-2 band fast.

**AI brain (how the enemy commander uses or counters it):**

The enemy commander/fire-control already has the exact counter and reads ONLY sensors: sim/enemy_defense.py _try_sm6_launch engages any tracked missile whose dead-reckoned altitude ey >= SM6_AREA_MIN_ALT_M and ground range in [50 km, 240 km], farthest-first ('reach out and kill early'). The ASBM's lofted midcourse is a fat, high, clean SM-6 target — so the enemy's intended answer is 'shoot it on the way up/over with the SM-6 long-range area round'. The ASBM's counter-counter is the fresh-track + steep terminal dive: by the time it noses over, it is plummeting through the SM-2 band at very high speed with little crossing time, and a stale launch track means the SM-6 midcourse was aimed at where the ship WAS. No new AI code is required for v1 — the SM-6 channel already fires on the picture; an OPTIONAL Phase-2 add is a commander preference to spend SM-6 farthest-first on the highest-closing-rate track (a ranking tweak in _try_sm6_launch, still sensor-only). The enemy must NEVER read the ASBM's true apogee/target; it only has its own SM-6/SM-2 tracks.

**Player UX:**

Tactical map (M): select a ship contact (LMB) exactly as for the Oniks; press B until the Bastion round reads 'ASBM' (HUD weapon line); SPACE fires the next ready tube. There is NO hi-lo/lo-lo profile choice (1/2 keys are ignored for ASBM — it has one ballistic regime); instead a single 'LOFT' arc is always flown. The map shows a distinct ballistic arc preview (apogee marker) vs the Oniks' flat route, and a TIME-TO-IMPACT countdown (the long ToF is the whole point — the player must commit early and keep the track fresh with the drone). A HUD hint warns when firing on a STALE surface track ('TRACK AGE 45s — ASBM MAY MISS A MOVER').

**UI needs:**

NEW: (1) weapon-line readout 'ASBM x N' with ammo, mirroring the existing Oniks/Zircon HUD rows (game/hud.py). (2) Map arc-preview render: a parabola from the TEL to the aim point with an apogee dot + altitude label (tactical_map.py draw pass — new helper alongside the existing flat PLAN_COL route line). (3) Time-to-impact / track-age strip on the HUD threat area. (4) A B-cycle hint toast 'BASTION: ASBM (TOP-ATTACK)'. Feeds the consolidated UI plan's 'weapon selector + per-round info card' surface.

**Game-model mapping (reuse vs add):**

REUSE sim/arsenal.py SamDef (it already carries loft_gain/loft_bias_max/loft_fade_range read per-round by sim/sam.py _aim_direction). ADD a SamDef ASBM constant (long burn, high loft_bias_max ~ 60 km, terminal_range for the dive handover, min/max_intercept_alt set to the SEA band so the ARH terminal works at the surface — note the 40N6's 4 km floor must NOT be copied; ASBM dives to the deck). REUSE sim/sam.py SamMissile UNCHANGED for boost/loft/coast/terminal-PN/fuse — but it must target a SHIP and refine onto the hull at terminal. The cleanest path: a thin AsbmMissile(SamMissile) subclass whose terminal phase, instead of the air-target PN, runs the Oniks' _acquire_lock-style nearest-ship seeker (port the seeker cone logic from sim/missile.py _acquire_lock) so the MaRV captures the real hull through the existing proximity fuse-on-truth. ADD to WEAPONS-adjacent registry an ASBM entry and an ammo pool. REUSE world/combat.py launch(): extend weapon_id branch to 'asbm', pulling from self._asbm_ammo and spawning AsbmMissile from the ready tube aimed at the selected ship/target_point with contact_estimate_fn=self._contact_estimate(selected_contact). REUSE the player-vs-enemy structure/ship damage sweep unchanged (AsbmMissile is a player round, is_hostile=False, killed via fuse like any SamMissile vs a ship target — note SamMissile._fuse_check already duck-types target.kill()).

**Implementation sketch + test contracts:**

Files to touch: sim/arsenal.py (ADD ASBM SamDef + ASBM_AMMO + register), sim/sam.py or NEW sim/asbm.py (ADD AsbmMissile(SamMissile) overriding the terminal seeker to lock the nearest alive ship in cone — copy the cos_half/seeker_range loop from sim/missile.py _acquire_lock; everything else inherited), world/combat.py (launch() weapon_id=='asbm' branch + self._asbm_ammo from config + arc target = ship contact estimate; add to the _zircon_ammo-style scarce pool plumbing in __init__), world/combat_config.py (ADD asbm_ammo field + CLAMP, default ~3-4), game/sandbox.py (extend cycle_oniks_weapon to 3-state + request_launch ASBM branch reusing the ship-contact path; skip the hi-lo/lo-lo envelope warning, add the stale-track hint), game/hud.py + game/tactical_map.py (weapon row + arc preview + ToF). TEST CONTRACTS (mirror tests/test_s300_rounds_distinct.py's measured-flyoff style, GL-free, deterministic): test_asbm_lofts_high_and_dives_near_vertical (flyoff vs a static ship at 250 km: apogee >= 40 km AND terminal flight-path angle steeper than -60 deg measured from vel at handover); test_asbm_kills_stationary_ship_in_envelope (fuse kill on a hull); test_asbm_misses_fast_mover_on_stale_track (launch on a frozen contact_estimate while the ship has since moved > fuse_radius+seeker reacquire — closest > fuse_radius, encoding the fresh-fix requirement as physics); test_asbm_fresh_track_kills_same_mover (same mover but contact_estimate_fn refreshed → kill, proving it is the STALE picture not the airframe that misses); test_asbm_high_midcourse_is_sm6_targetable (assert dead-reckoned midcourse altitude stays > SM6_AREA_MIN_ALT_M over the cruise — locks the counter contract); test_asbm_determinism (same seed → identical trajectory). Reuse the _World/_StaticTarget/_MovingTarget stubs from test_s300_rounds_distinct.py.

**Counters / balance:**

Balance contract: the ASBM is the anti-SCREEN tool but is COUNTERED by (a) the SM-6 area shot on its exposed high midcourse (physics: the enemy's 240 km clean-track band — already coded), and (b) its own long time-of-flight vs a maneuvering/repositioning fleet (the stale-track miss is emergent from guiding on a dead-reckoned point, never a roll — same mechanism as the S-300 firing on a stale contact). The player's mitigation is to keep the track FRESH with the drone (recon-fire loop) and/or salvo ASBM+lo-lo Oniks together so the SM-6/SM-2 channels are split. Fog-of-war contract: the enemy fires SM-6 only on tracks its SPY-1/AWACS forms (sensor-only); the ASBM's terminal seeker corrects the stale picture only in the last seconds (truth at the fuse). Scarcity (small ammo pool) keeps it from trivializing the carrier.

## Feature: Loitering-munition swarm with coordinated time-on-target (bundle-launch + simultaneous-arrival speed control)  _(effort: L)_

**What it is + real-world grounding:**

A canister of small subsonic loitering munitions the player launches as a BUNDLE on one button press; the player sets predetermined waypoints AND a single aim point that ALL rounds reach SIMULTANEOUSLY from their different positions/path-lengths by self-adjusting cruise speed. Saturation is the point: a coordinated time-on-target arrival overwhelms ship point-defense (CIWS/SM-2 can only service a few rounds at once). Grounded in open loitering-munition data: Switchblade-600/Lancet-class subsonic loiterers (40+ min endurance, ~40 km range, ~130-160 km/h cruise — https://www.avinc.com/solution/switchblade-300-block-20/ ; armyrecognition Switchblade), and coordinated simultaneous-arrival is a documented multi-munition technique to deny the target reaction/cover time (USPTO 11971731 'Coordinating spatial and temporal arrival of munitions'; arXiv 2303.16951 'Optimal Trajectories for Multiple-UAS Simultaneous Target Acquisition'). Fictionalized loiterer name e.g. 'KUB-swarm'.

**Platform (launched from / carried by):**

Player — a NEW dedicated launcher: a multi-cell loitering-munition pod (config.n_swarm_pods / per-pod cell count), placed at the base cluster like the Pantsir/S-300 TELs. Decision rationale: unlike the ASBM it does NOT fit the Bastion (different airframe class, many small rounds, a bundle/canister), and it needs its own destructible Structure + magazine. It is a friendly ground asset (is_hostile=False) that walks the structure damage ladder. Enemy does NOT field it in v1 (asymmetry; the enemy's saturation tool is the existing coordinated TLAM+JASSM+HARM package idea in GAME_ANALYSIS §7). Each cell holds one loiterer; a BUNDLE press fires all currently-ready cells together.

**Sensors (uses / detected by):**

USES: each loiterer's own small seeker (an EO/IR or active-RF terminal seeker, modeled like the Oniks' nearest-ship-in-cone _acquire_lock at a SHORT seeker_range — these are small munitions) plus the SHARED player ContactBoard for the commanded aim point. Because they are subsonic and small they can fly UNDER the horizon to a sea-skim ingress (lo profile) and pop to acquire at the aim point — the swarm-vs-fleet ingress mirrors the lo-lo Oniks but slower and in numbers. DETECTED BY: the enemy radar net at radar_size 'missile' (they are small/slow → arguably a 'stealth'-ish low-RCS class, but v1 uses 'missile' for the existing gate; an OPTIONAL refinement is a new low-RCS size class with a shorter detect range, feeding the consolidated radar-class table). The swarm's slow speed means a longer exposure window — countered by the simultaneous arrival compressing the terminal engagement into one instant.

**AI brain (how the enemy commander uses or counters it):**

Enemy point-defense reads ONLY its sensor tracks and is the designed counter: sim/enemy_defense.py SM2_MAX_INFLIGHT=4 (raid cap), the 3 s fire-control reload, and the CIWS 2 km bubble. A coordinated time-on-target means N loiterers cross the CIWS/SM-2 envelope in the SAME few seconds, exceeding the 4-in-flight SM-2 cap and the single CIWS channel per ship — so leakers get through by SATURATION, emergent from the existing in-flight caps, not a probability. The enemy's honest mitigations (all sensor-only, mostly already present): (1) ships maneuver/concentrate fire on the nearest tracks (the existing nearest/assigned-fewest ranking in _try_sm2_launch handles spread automatically); (2) the AWACS/SM-6 can pick off the slow loiterers EARLY on their long ingress if they fly high (so the player flies them LOW — re-using the multipath domain). OPTIONAL Phase-2 AI: a commander 'pop-up raid detected' reaction that raises silenced ship radars when many missile-class tracks appear in one sector (reuse the existing _drone_sector_alert pattern — sensor-triggered). The AI must never see the swarm's commanded arrival time or waypoints; it only counts the missile tracks it forms.

**Player UX:**

Tactical map (M): TAB to the 'swarm' platform (extend PLATFORMS_COMBAT). Plan: RMB drops shared waypoints (the existing add_waypoint flow, already capped at 8); LMB sets the single aim point on a ship contact or a coordinate. A NEW key/toggle sets ARRIVAL MODE (e.g. 'SYNC' on by default) — when on, all rounds reach the aim point at the same instant by self-adjusting speed; off = each flies max speed. SPACE = BUNDLE launch: every ready cell fires together. The map shows each round's planned path and a single shared TOT (time-on-target) countdown; in SYNC mode the slowest/longest path sets the TOT and the others throttle to match (shown as per-round speed bars). The player can also set a per-round fan-out (different ingress bearings) by dropping waypoints that split the bundle — the spec keeps v1 to one shared route with auto speed-sync; multi-route fan-out is an easy extension since each Missile already owns its route.

**UI needs:**

NEW high-quality UI: (1) a SWARM TASKING panel on the tactical map — list of cells (loaded/empty), the shared aim point, the TOT countdown, an ARRIVAL-MODE (SYNC/MAX) toggle, and per-round commanded-speed bars (so the player SEES the slow round setting the pace and the fast rounds throttling). (2) A 'bundle ready: N cells' indicator + a one-press BUNDLE LAUNCH affordance. (3) Map: N path lines converging on one aim cross with a synchronized arrival ring that contracts to the TOT. (4) HUD swarm row (cells remaining, in-flight count). This is the cluster's biggest NEW UI surface and directly serves the project's 'more, higher-quality UI' goal.

**Game-model mapping (reuse vs add):**

REUSE sim/missile.py Missile heavily: it ALREADY owns a route (waypoints + final target_point), Mach-hold _sustainer_thrust, terminal _acquire_lock + PN + fuse, and a per-salvo weave seed. ADD a WeaponDef SWARM constant (small, subsonic cruise_mach_lo ~0.2-0.45, modest fuel for ~40 km, short seeker_range). The simultaneous-arrival is a NEW thin layer: compute per-round commanded ground speed v_i = path_length_i / T_arrival, where T_arrival = max_i(path_length_i)/v_cruise_max + margin (the slowest/longest path at max speed sets the bus time, everyone else throttles). Implement as a NEW Missile field commanded_cruise_speed (m/s) that, when set, OVERRIDES the Mach-hold target in _sustainer_thrust (target_mach = commanded_speed/local_a) — a few lines in _sustainer_thrust reading an optional self._commanded_speed. The path length is the existing route polyline length from the launch tube through the waypoints to the aim point (a sum of segment hypots — same math already in _plan_vertical_profile's d_route). ADD a SwarmPod Structure + magazine to world/combat.py mirroring the Pantsir wrapper (destructible, config-driven). The BUNDLE launch is a new world method launch_swarm(profile, aim_point, waypoints, sync: bool) that spawns one Missile(SWARM,...) per ready cell, computes each path length, derives the shared T and per-round commanded speed, and sets _commanded_speed on each (salvo ordinal seeds the weave so they don't formate). DETERMINISM: no new RNG needed beyond the existing per-salvo weave (deterministic by ordinal); if a low-RCS noise term is added later it follows the seeded child-stream pattern.

**Implementation sketch + test contracts:**

Files to touch: sim/arsenal.py (ADD SWARM WeaponDef + a SWARM_POD LauncherDef with tubes/cells + SWARM_AMMO; register in WEAPONS so the renderer/round logic resolve it). sim/missile.py (ADD optional self._commanded_speed=None in __init__ and, in _sustainer_thrust, if set use target_mach=commanded_speed/mach-denominator instead of cruise_mach — guard so unset = bit-identical existing behavior; ADD a tiny set_commanded_speed/arrival helper). NEW sim/swarm.py OR a world method: compute_swarm_speeds(launch_pos, per_round_routes, v_max, margin) -> list[v_i] (pure function: path_length via segment hypots, T = max_len/v_max + margin, v_i = len_i / T, clamp to [v_min, v_max]) — UNIT-TESTABLE headless. world/combat.py (ADD SwarmPod structures + _swarm_cells magazine + launch_swarm() bundling all ready cells, calling compute_swarm_speeds and set_commanded_speed per round; cells reload from a pool like the Oniks tubes). world/combat_config.py (ADD n_swarm_pods, swarm_cells_per_pod or swarm_ammo, swarm_mag_reload_s + CLAMPs). game/controls.py (ADD 'swarm' to PLATFORMS_COMBAT; ADD a 'swarm_arrival_mode' bindable action). game/keybinds.py (ADD the ARRIVAL-MODE action default key). game/sandbox.py (request_launch swarm branch -> world.launch_swarm; TAB platform handling). game/tactical_map.py (the swarm tasking panel + converging path render + TOT ring + the shared-aim-point flow reusing add_waypoint). game/hud.py (swarm row). TEST CONTRACTS: test_compute_swarm_speeds_simultaneous (3 rounds, different path lengths, all arrive within EPS seconds of each other when each flown at its v_i — assert max(arrival_t)-min(arrival_t) < ~1 s in a flyoff, AND the longest path runs at ~v_max while shorter paths run slower); test_commanded_speed_overrides_mach_hold (a Missile with _commanded_speed holds that ground speed in cruise, measured); test_unset_commanded_speed_bit_identical (an Oniks with no commanded speed flies the EXACT existing trajectory — regression guard on the _sustainer_thrust edit); test_bundle_launch_fires_all_ready_cells (launch_swarm spawns N rounds, decrements the magazine by N, sets distinct salvo ordinals so weaves differ); test_swarm_saturates_point_defense (a CombatWorld e2e: a synchronized N-round bundle vs one destroyer produces >= 1 leaker hit where a 4-round non-synced trickle does not — the saturation contract, mirroring tests/test_phase6_e2e.py style); determinism replay test.

**Counters / balance:**

Balance contract: saturation EMERGES from the enemy's existing in-flight caps (SM2_MAX_INFLIGHT=4 per ship, 3 s reload, single CIWS channel/2 km bubble) — a coordinated TOT puts more rounds in the terminal window than the defense can service, so leakers get through WITHOUT any kill roll (physics-not-dice). Counterplay for the enemy (all sensor-driven): early SM-6/AWACS attrition of the slow loiterers on their long ingress IF they fly high (drives the player low into the multipath band), ships concentrating fire via the existing nearest/fewest-assigned ranking, and raising silenced radars when a multi-track raid is sensed (reuse _drone_sector_alert). Fog-of-war contract: the enemy never sees the commanded arrival time or routes; it only forms missile-class tracks of the rounds its radars physically detect. Determinism: per-round weave is seeded by ordinal; the speed-sync math is pure/deterministic. Scarcity + slow speed (long exposure) + the high-altitude SM-6 vulnerability keep the swarm from being a free win against a carrier screen.
