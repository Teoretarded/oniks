# Spec 9: Map terrain + graphics upgrade, then seeded presets

> Implementation-research spec for a fresh implementer. Read HANDOFF_README.md first for codebase orientation + non-negotiables.

## Summary
Four features, sequenced. (1) **Terrain quality** — lift the EXISTING default map's heightfield and look (more octaves of detail, real coastal cliffs vs. beaches, slope+height material grading, cleaner normals) WITHOUT moving the gameplay-critical elevations (base/SAM/Pantsir pad heights, island peaks, the radar-horizon-defining coast) and WITHOUT changing a single sim output bit on the default map. (2) **Graphics quality** — renderer-only ocean/water shading (foam at shorelines + wave crests, a sea-state hook), sky/atmosphere/lighting depth, and distance fog/haze tuning, all behind a **Low/High quality toggle** kept inside the existing one-ortho-flush + quad-budget discipline; zero sim change. (3) **HeightField refactor** — wrap the field that today lives as the free functions `terrain_height` / `terrain_height_scalar` / `surface_height_scalar` in a `HeightField` class and make the sensor/missile LOS path (`sim/radar.terrain_blocks`, already pluggable via its `height_fn` arg) take a field instance, so a NEW map can be swapped in everywhere at once — gated by a **bit-identical-on-DEFAULT** regression contract. (4) **Seeded map presets** — Open Sea / Archipelago / Narrow Strait / Fjord Coast selectable on the setup screen, each a deterministic field built from `np.random.default_rng([seed, tag])`, that finally EXERCISE terrain-masking + the radar-horizon physics (the existing `terrain_blocks` gate is under-used on today's mostly-open ocean; islands and fjord walls make it bite — for sensors AND missiles, both ways).

**IMPORTANT factual correction to the prior draft** (the previous stub and the orchestrator brief both got this wrong): there is **already** a `terrain_blocks(a, b, height_fn=terrain_height_scalar)` function — it lives in `sim/radar.py` (lines 34-46), and it is **already** the shared LOS gate for radar detection (`sim/radar.Radar.detects`), SAM/missile LOS (`sim/sam.py` line 325) and the drone's SAR/ELINT LOS (`sim/recon.py` lines 211/466/535). There is **no `HeightField` class yet** (confirmed — no definition anywhere in the tree). So Feature 3 is NOT "write `terrain_blocks` from scratch"; it is "introduce a `HeightField` object and route the *existing* `height_fn` seam through it so presets can replace the field globally." Everything in this spec is written against that real seam — `height_fn` is the load-bearing injection point that makes presets honest and DRY.

**Dependencies:** Build order is the section order, and it is a real dependency chain. (1) Terrain quality and (2) graphics quality are independent of each other and of the rest — do them first/in parallel; both are self-contained polish with hard regression gates and NO new gameplay. (3) HeightField is the REQUIRED prerequisite for (4): presets need a way to install a different field into `sim/radar.terrain_blocks`, `sim/sam.py`, `sim/recon.py`, `sim/aircraft.py`, `sim/enemy_air.py`, `sim/missile.py` (the `TERRAIN_MAX_HEIGHT` consumers) and the three renderers (`world/terrain.py`, `world/ocean.py`, `world/sky.py`) — without each importing the module-level functions directly. (4) Presets depend on (3) AND on (1) being done (a preset should ship the upgraded look, not the old one). Cross-cutting: the CombatConfig schema is **LOCKED** (`world/combat_config.py` docstring demands integrator sign-off) — Features 2 and 4 each add ONE field (`graphics_quality`, `map_preset`) + a clamp/enum + a setup row, and that schema change needs the sign-off the file's docstring requires. Determinism: every preset field is built from `np.random.default_rng([seed, tag])` with FRESH tags (3..7 are taken in `world/combat.py`: fleet 3 / recon 4 / commander 5 / pantsir 6 / radars 7) — reserve **[seed, 12] map-terrain** here (8/9/10/11 are claimed by Spec 6). The graphics toggle is a render-only enum and uses no RNG.

**Open questions:** 1) Should `graphics_quality` (Low/High) live in CombatConfig (replayable, set at setup) or as a runtime keybind toggle (changeable mid-battle, not part of the seed)? Recommend BOTH: a CombatConfig default + a runtime hotkey that overrides for the session (render-only, so it never touches determinism). 2) Map preset as a CombatConfig enum field (`map_preset: str`) — string or int? Recommend a small int enum with a names table (clamps cleanly, survives `clamp_config`). 3) Do presets relocate the player base / SAM / Pantsir pads, or keep them fixed and only change the *surrounding* sea/islands? Recommend keeping the home-coast base cluster geometry stable (so armory/UX/tests don't churn) and varying the ENEMY-side approaches + mid-ocean islands — that's where terrain-masking gameplay lives. 4) Does the enemy commander need terrain-aware routing for v1 (ingress through gaps, mask behind islands), or is "no AI change for v1, the existing `terrain_blocks` gate already makes islands matter to its sensors" acceptable? Recommend NO AI change for v1 — call it out as the highest-value follow-up. 5) The `TERRAIN_MAX_HEIGHT = 430.0` constant is a perf invariant (flyers above it skip ground queries) — must every preset stay under it, or does Fjord Coast want taller walls (and a per-field max)? Recommend each `HeightField` carries its own `max_height` and the `430.0` module constant becomes the field's attribute (default unchanged). 6) Foam needs a shoreline signal — derive it in-shader from depth (`max(-terrain, 0)` is not available at the ocean vertex; the ocean is a flat ring grid with no terrain sample) or bake a coarse coastal-distance field? Recommend an in-shader cheap approximation from the wave-displaced normal + a coarse CPU "near-shore" weight uploaded per ring (details in F2).

## Feature: Improve the existing map's terrain quality  _(effort: M)_

**What it is + real-world grounding:**

Raise the visual and tactile quality of the DEFAULT map's land — finer multi-octave relief so coastlines and island flanks read as real geology instead of smooth noise; genuine **coastal cliffs** where the shore is steep and **beaches/foreshore** where it is shallow; **material grading by slope and height** (sand at the waterline, grass/scrub on gentle ground, exposed rock on steep faces, bare high rock on peaks) with seam-free normals across tile/LOD boundaries. Grounded in real coastal morphology: wave-cut bluffs vs. depositional beaches, vegetation that thins with altitude and disappears on cliff faces. The current generator (`world/generation.py`) ALREADY has the bones of this — a cliff band (`_CLIFF_H`/`_CLIFF_RUN`/`_CLIFF_FOOT`, the "S5 terrain pass"), an `fbm` height ramp, and a slope+height `_colorize` in `world/terrain.py` — so this feature is a *quality lift of an existing system*, not a rewrite. The hard constraint is that it must not disturb the elevations gameplay reads.

**Platform:**

N/A — terrain carries no platform. But it is the SURFACE that gameplay-critical entities sit on and the LOS occluder for all of them: the player base (`BASE_POS`), the S-300 site (`SAM_SITE_POS`), the Pantsir pads, the radar station, the relocatable TELs (Spec 6), the enemy coastal radars (the win condition), Harbor KILO, and the hand-placed islands all derive their Y from `terrain_height`. Their (x, z) positions and the heights at those points are LOCKED gameplay values — see the regression gate below.

**Sensors (uses / detected by):**

CRITICAL — terrain IS the LOS occluder, so its detail changes how radar/SAR/ELINT see, and the contract is: **on the DEFAULT map the answer must not change**. `sim/radar.terrain_blocks` samples the field every `LOS_STEP_M = 2_000` m between sensor and target; a quality lift that only adds detail at wavelengths shorter than ~400 m (the current finest noise) and that keeps the sampled heights bit-identical at the SSOT level cannot change a single `terrain_blocks` result. The rule for this feature: **all added detail is either (a) render-only (in `world/terrain.py` colors/normals, never in `world/generation.py`), or (b) if it touches `world/generation.py` height, it is gated behind the preset system (Feature 3/4) and the DEFAULT field stays byte-identical.** Net for v1: the cliff/beach *look* improvements that are purely material/normal go in the renderer; any genuine new height shaping ships as a NEW preset (e.g. "Fjord Coast" gets the dramatic walls), so the default map's sensor behaviour is frozen. This keeps fog-of-war honest (no truth leak from a prettier hill that the sim doesn't know about) and the sim bit-identical where it matters.

**AI brain (how the enemy commander uses or counters it):**

No AI change for v1. The enemy commander (`sim/commander.py`) reads only its own radars' gated picture; because the default field is unchanged, its behaviour is identical. (When Feature 4 ships taller terrain on new presets, the AI automatically "sees less" through it via the same `terrain_blocks` gate — still no code change, the masking is emergent. Terrain-aware ingress routing is the named follow-up, out of scope here.)

**Player UX:**

The map simply looks better — cliffs and beaches read at a glance, the SAM hilltop and enemy coast are visually legible, relief communicates dead ground. No new controls. The tactical map (`game/tactical_map.py`) terrain shading should stay consistent with the 3D look (it samples the same field), but no behaviour change.

**UI needs:**

None new. The improvements are in the existing terrain color/normal pipeline. The Low/High toggle that gates the *expensive* parts is Feature 2's surface (terrain detail level is one of the things the toggle scales — High enables LOD0 60 m tiles + the richer material blend, Low caps at LOD1 + a cheaper 2-blend material).

**Game-model mapping (reuse vs add):**

REUSE and extend, do not rewrite. (a) `world/terrain.py::_colorize` — the slope/height material function: add the cliff-vs-beach discrimination (a beach band that widens where slope is low near the waterline, a rock face that engages where slope is high) and richer mottling; it is already a pure elementwise function of world position so abutting tiles stay bit-identical (the seam test). (b) `world/terrain.py::_mesh_steps` central-difference normals — verify the halo margin still feeds seam-free normals after any change to the slope thresholds. (c) `world/generation.py` cliff constants (`_CLIFF_H/_RUN/_FOOT`) — leave the DEFAULT values frozen; only the preset fields (Feature 4) vary them. (d) LOD config `LODS`/`_TILE`/`_BUILD_BUDGET_S` — High quality may add a 30 m LOD0+ tier IF the frame-time gate holds; otherwise keep three LODs and just enrich color/normals. ADD nothing to `world/combat_config.py` for this feature (terrain quality rides Feature 2's `graphics_quality` toggle).

**Implementation sketch + test contracts:**

Files: `world/terrain.py` (`_colorize` material grading + any normal-quality tweak; optional High-only LOD0 tier), `world/generation.py` (NO change to the default field; comments only). Helper: extract the beach/cliff/rock/peak blend into named sub-functions of `_colorize` for testability. TEST CONTRACTS: (a) **bit-identical default field** — `tests/test_generation.py` must still pass unchanged, including `test_scalar_fast_path_bit_identical`, `test_surface_height_scalar_matches_max_terrain`, and the base/SAM/island/site height asserts; add an explicit `test_default_field_heights_frozen` pinning `terrain_height` at `BASE_POS`, `SAM_SITE_POS`, every Pantsir pad, the radar station, and each `ISLANDS` peak to their current float values. (b) **seam-free colors** — a test that `_colorize` at a shared vertex of two abutting tile rects returns bit-identical RGB (pure-function property). (c) **material bands sane** — `_colorize` returns sand near h∈[0,3] m, rock where slope>0.24, high-rock near `h_ref`, grass on gentle mid ground (assert the dominant channel ordering at sample points). (d) **terrain_blocks unchanged on default** — a probe (`tools/probe_terrain_los_default.py`) computes `terrain_blocks` over a fixed grid of sensor/target pairs and asserts it equals a stored baseline (the masking regression). (e) frame-time: covered by Feature 2's gate.

**Counters / balance:**

No gameplay balance change on the default map by construction (heights frozen). The only "balance" lever is visual legibility — cliffs must not be so dark they hide the enemy radar markers; the existing `_colorize` height-brightening guards against grey-out (it was tuned in S5 to stop washing the SAM hilltop concrete-grey — keep that fix).

**Risks:**

The dominant risk is silently perturbing a gameplay height. Mitigation: the frozen-heights test (a) and the LOS baseline (d) are non-negotiable gates; treat any diff there as a build failure. Secondary: a slope-threshold change in `_colorize` could reintroduce a lighting seam if it reads beyond the halo margin — keep the central-difference window inside the existing `_LOD1_MARGIN`/halo. Scope creep: do NOT add height detail to the default field "while you're in there" — that belongs in a preset.

## Feature: Improve graphics quality (ocean / sky / lighting / fog) + Low/High toggle  _(effort: M)_

**What it is + real-world grounding:**

A renderer-only visual uplift with a quality toggle: richer **ocean/water** (the existing 4-directional Gerstner-ish sine field + sun glint gains **foam** at wave crests and along shorelines, plus a **sea-state hook** so wave amplitude/choppiness can be dialed — calm vs. moderate), deeper **sky/atmosphere/lighting** (a graded multi-stop sky gradient, a softened horizon band, a tuned sun glow, hemispheric fill that reads relief better), and **distance fog/haze** tuned so the 600 km world fades convincingly without hiding tactical contacts. All grounded in real maritime optics: foam streaks on whitecaps and surf, the way haze thickens toward the horizon and warms toward the sun, the blue-shift of the deep sea vs. the bright Fresnel rim at grazing angles. A **Low/High** toggle scales the cost: Low keeps today's look (cheap), High enables foam + the extra sky stops + (optionally) the finer terrain LOD from Feature 1 — all inside the existing render budget.

**Platform:**

N/A. Renderer modules only.

**Sensors (uses / detected by):**

NONE — this feature is **renderer-only and must not change one sim bit**. The sim never imports `world/ocean.py`, `world/sky.py`, `engine/renderer.py`, or `engine/shaderlib.py` (they import OpenGL; unit tests run headless). Foam, sea-state and fog live entirely in shaders + the GL wrappers. The sea-state "hook" is a *visual* uniform (`u_sea_state`), NOT a sim wave field — sea-skimming altitude logic stays in `sim/missile.py` against `surface_height_scalar` (which returns the y=0 ocean plane), unchanged. This is the fog-of-war / physics-not-dice firewall: prettier water cannot make a missile hit or a radar see.

**AI brain (how the enemy commander uses or counters it):**

No interaction — the AI is sim-side and never reads the renderer. Stated explicitly so no one wires a "rough seas degrade radar" shortcut here; if sea-state should ever affect detection, that is a sim feature (a real multipath/clutter term in `sim/radar.py`), not a shader uniform.

**Player UX:**

A visibly better sea and sky; the player can pick **Low** (older HW / max FPS) or **High** (full effects). The toggle is reachable at setup (a CombatConfig default) and, recommended, via a runtime hotkey so the player can drop to Low if frames sag mid-battle — render-only, so flipping it never affects the seed/determinism. Fog tuning must keep enemy contacts and the tactical overlays readable at range (the haze should fade *terrain*, not the contact carets, which are drawn in the ortho HUD pass).

**UI needs:**

(1) A **GRAPHICS** row on the setup World page (`game/combat_setup.py` `_WORLD_ROWS`) — a new row `kind: "enum"` (a cyclic LEFT/RIGHT choice, sibling to the existing "stepper"/"fixed"/"seed"/"action" kinds) showing `LOW` / `HIGH`, bound to a new `graphics_quality` CombatConfig field. (2) An optional runtime keybind (e.g. a "graphics quality" toggle in `game/keybinds.py` + `game/controls.py`) that flips the live setting. (3) A tiny HUD indicator is optional (not required). The toggle must respect the **single ortho flush / quad-budget** discipline: any new HUD/foam-debug text reuses the one text pass; foam is drawn IN the existing ocean draw (no extra GL passes, no second flush).

**Game-model mapping (reuse vs add):**

REUSE the existing shader plumbing. (a) `world/ocean.py` `OCEAN_FRAG` — add foam: a crest term from the wave height/normal already computed in `OCEAN_VERT` (pass `v_wave_h` or reuse the steepness from the cosine derivatives) and a shoreline term from a per-ring "near-shore" weight (a coarse CPU value uploaded per ring in `Ocean.draw`, sampled from a downscaled coastal-distance lookup — cheap, computed once at load from the field). Add `u_sea_state` (scales `a0..a3` amplitudes / steepness) and `u_quality` (gates foam + glint cost). (b) `world/sky.py` `SKY_FRAG` — extra gradient stops + horizon band + tuned glow; gate the extra math on `u_quality`. (c) `engine/shaderlib.py` `HAZE_GLSL` / `engine/renderer.py` `HAZE_DENSITY`/`HAZE_COLOR`/`SUN_*` — tune the haze curve and expose density/sea-state via `set_common` so all lit shaders + the ocean stay consistent (haze is already shared via `HAZE_GLSL` — keep it DRY). (d) ADD ONE CombatConfig field `graphics_quality: int = 1` (0=Low,1=High) + `CLAMP_GRAPHICS = (0, 1)` + clamp_config wiring (LOCKED schema — sign-off). The setting flows world -> `Renderer`/`Ocean`/`Sky` as a uniform; **no GL import crosses into `sim/` or `world/generation.py`.**

**Implementation sketch + test contracts:**

Files: `world/ocean.py` (foam + sea-state + quality uniforms in `OCEAN_VERT`/`OCEAN_FRAG` + `Ocean.draw` uploads the per-ring near-shore weight and the quality/sea-state floats), `world/sky.py` (graded sky + quality gate), `engine/shaderlib.py` + `engine/renderer.py` (haze tuning + `u_quality`/`u_sea_state` in `set_common`), `world/combat_config.py` (`graphics_quality` + clamp), `game/combat_setup.py` (the `enum` row kind + GRAPHICS row), optional `game/keybinds.py`/`game/controls.py` (runtime toggle), `game/sandbox.py` (pass the live quality into the renderers). New constants: `SEA_STATE_DEFAULT`, foam thresholds, sky gradient stops — all in the GL modules. TEST CONTRACTS: (a) **headless import safety** — `tests/test_combat_config.py` gains `graphics_quality`/clamp asserts; a test that `world/ocean.py` and `world/sky.py` still import without OpenGL at module level (the GL-free contract — they defer `Mesh`/`Shader` to `__init__`, except `world/sky.py` which already imports `OpenGL.GL` at top; keep its existing pattern, just don't add sim-visible state). (b) **sim bit-identical** — run the full combat regression (the phaseN_e2e tests + smoke gate); graphics changes must leave them untouched (they don't import the renderer, so this is a sanity assertion, not a new test). (c) **frame-time gate** — extend/author `tools/probe_frametime.py` (headless GL or a render-loop harness) asserting High stays within the project's frame budget and Low is cheaper; the single-ortho-flush invariant is checked by counting flushes per frame (must be 1). (d) the `enum` setup row: `tests/test_combat_setup.py` asserts LEFT/RIGHT cycles `graphics_quality` within `CLAMP_GRAPHICS` and START emits a config carrying it.

**Counters / balance:**

No gameplay balance (render-only). The "balance" is perf vs. fidelity: High must stay inside the budget on the reference machine, Low must be a real fallback (measurably cheaper). Fog density is the one knob that could accidentally *help or hurt* the player perceptually (too thick hides the enemy coast) — tune so terrain fades but contacts/HUD (drawn in the ortho pass) never do.

**Risks:**

(1) Budget blow-out: foam + extra sky math + finer terrain could exceed the frame budget — the High/Low gate and the frametime test exist to catch it; if High can't fit, ship foam-only-near-camera. (2) The single-flush discipline: do NOT add a second ortho pass or an extra full-screen quad for foam/fog — fold them into the existing ocean/sky draws. (3) Shoreline foam needs a coast signal the flat ocean grid lacks — the per-ring coarse near-shore weight is the pragmatic answer; a per-vertex terrain sample on the ocean would be a perf trap (avoid). (4) Determinism scare: keep `graphics_quality` strictly render-side; never let it branch any sim/world height or RNG.

## Feature: HeightField refactor (class wrapping the field) + field-routed `terrain_blocks` LOS  _(effort: M)_

**What it is + real-world grounding:**

A structural refactor — the prerequisite for new maps. Today the world's shape is a set of module-level functions in `world/generation.py` (`terrain_height` vectorized, `terrain_height_scalar` scalar fast path, `surface_height_scalar` clamped-to-y=0 fast path) plus the constants they close over (`SEED`, `ISLANDS`, `ENEMY_COAST_Z`, the coast/cliff/shelf tuning, `TERRAIN_MAX_HEIGHT`). A different map cannot be installed because callers import those functions directly. This feature introduces a **`HeightField`** class that owns those parameters and exposes `height(x, z)` (vectorized), `height_scalar(x, z)`, `surface_scalar(x, z)`, plus `max_height` (the per-field analogue of `TERRAIN_MAX_HEIGHT`) and an `rng_tag`/`seed` identity. The crucial seam already exists: `sim/radar.terrain_blocks(a, b, height_fn=...)` and the recon/SAM LOS calls all take a `height_fn` callable — so a `HeightField` instance's bound `height_scalar` method drops straight in as that `height_fn`. The refactor's whole job is to make the field **swappable in one place** while staying **bit-identical to today on the DEFAULT map** (the regression gate). No real-world grounding — this is engineering scaffolding for Feature 4.

**Platform:**

N/A. It is the data structure every on-terrain entity and every LOS query reads through.

**Sensors (uses / detected by):**

This feature is ABOUT the sensor seam, and the non-negotiable is fog-of-war honesty + symmetry: **the player AND the enemy must read LOS through the SAME field.** Today `sim/radar.terrain_blocks` defaults `height_fn=terrain_height_scalar`, and radar (`Radar.detects`), SAM LOS (`sim/sam.py:325`), and drone SAR/ELINT (`sim/recon.py`) all funnel through it — so they already agree. The refactor must PRESERVE that: the active `HeightField` is created once in `world/combat.py` and its `height_scalar` is threaded as the `height_fn` to every sensor/missile/recon constructor (recon already accepts `height_fn`; `sim/radar.Radar` calls `terrain_blocks` with the default, so either pass the field down or set a per-world active field — see sketch). The enemy commander/back-plot reads the same surface. CRITICAL test: the AI's `height_fn` must be identical to the world's `height_fn` (no side reads truth, neither side reads a richer field than the other). The radar-horizon physics (`radar_horizon_m`, earth-curvature) is independent of the field and unchanged.

**AI brain (how the enemy commander uses or counters it):**

No AI logic change. The enemy's sensors get the same field instance, so on the default map its picture is bit-identical. On new presets it automatically sees less through islands/walls via the unchanged `terrain_blocks` — emergent, no code change. Add a test pinning enemy `height_fn is world height_fn`.

**Player UX:**

Invisible. Pure refactor; the player notices nothing on the default map (that's the point).

**UI needs:**

None. (The preset PICKER is Feature 4.)

**Game-model mapping (reuse vs add):**

ADD `world/generation.py::HeightField` wrapping the existing math. KEEP the module-level `terrain_height` / `terrain_height_scalar` / `surface_height_scalar` / `is_land` / `TERRAIN_MAX_HEIGHT` as thin shims that delegate to a module DEFAULT field — so every existing import keeps working byte-for-byte and the bit-identical gate is trivially met (the default field's code path IS the old code, just bound to `self`). The class fields are the current constants (`seed=SEED`, `islands=ISLANDS`, `enemy_coast_z=ENEMY_COAST_Z`, the coast/cliff/shelf params, `max_height=430.0`). `sim/radar.terrain_blocks` is REUSED unchanged (it already takes `height_fn`); the only wiring is: `world/combat.py` builds the active `HeightField`, stores it, and threads `field.height_scalar` into the radars/SAMs/recon/aircraft as their `height_fn`. For `sim/radar.Radar` (which calls `terrain_blocks` with its default), give `Radar` an optional `height_fn` ctor arg (default the module shim) so `world/combat.py` can pass the active field — a one-line, backward-compatible addition. `BASE_POS`/`SAM_SITE_POS`/`SAM_SITE` etc. are computed from the default field — unchanged. NO change to `world/combat_config.py` in THIS feature (the `map_preset` field arrives in Feature 4).

**Implementation sketch + test contracts:**

Files: `world/generation.py` (`HeightField` class + the existing functions become shims over a module `DEFAULT_FIELD = HeightField()`), `sim/radar.py` (add optional `height_fn` to `Radar.__init__`, used in `detects` -> `terrain_blocks`; `terrain_blocks` itself unchanged), `world/combat.py` (build the active field, thread `field.height_scalar` to `Radar`/SAM/recon/aircraft/enemy-air constructors; thread `field.max_height` where `TERRAIN_MAX_HEIGHT` is read for the skip optimization). TEST CONTRACTS — the regression GATE is the spine: (a) **bit-identical DEFAULT** — add `tests/test_heightfield.py`: for a large fixed grid of (x, z), `HeightField().height(...) == terrain_height(...)`, `.height_scalar(...) == terrain_height_scalar(...)` exactly (no float drift), and `.surface_scalar == surface_height_scalar`; ALL existing `tests/test_generation.py` pass unchanged. (b) **shim identity** — `terrain_height is` (or returns identically to) `DEFAULT_FIELD.height` for every input in the existing generation tests. (c) **LOS routing** — `terrain_blocks(a, b, height_fn=field.height_scalar)` equals `terrain_blocks(a, b)` (default) for the default field over a fixed sensor/target grid (the masking baseline from Feature 1's probe, reused). (d) **symmetry** — in a built `CombatWorld`, assert every `Radar`/SAM/recon object's `height_fn` is the SAME callable as the world's field's `height_scalar` (player AND enemy) — no truth leak, no asymmetry. (e) **`max_height` plumbed** — flyers above `field.max_height` still skip ground queries (the `sim/missile.py`/`sim/enemy_air.py` optimization) and results match. (f) the existing combat regression (phaseN_e2e + smoke) passes unchanged.

**Counters / balance:**

None (refactor). The contract that preserves the good loop: the default map plays EXACTLY as today, byte-for-byte, sensors and missiles included.

**Risks:**

(1) The bit-identical gate is everything — any float reordering inside the class (e.g. computing in a different order than the free function) can drift a last bit and fail `test_scalar_fast_path_bit_identical`. Mitigation: the class methods must execute the IDENTICAL arithmetic in the IDENTICAL order as the current functions (literally move the bodies, bind constants to `self`, change nothing else). (2) The `Radar` `height_fn` addition touches a tested file (`sim/radar.py`) — keep `terrain_blocks` and the default path behaviorally identical (regression test c). (3) Missing a `height_fn` thread-through (e.g. one enemy-air construction site left on the module shim) would silently keep the DEFAULT field on a preset map — break LOS honesty on new maps; the symmetry test (d) plus a preset masking probe (Feature 4) catch it. (4) `TERRAIN_MAX_HEIGHT` is imported as a module constant in several sim files; making it per-field means those imports must read `field.max_height` or the default stays 430 on a taller preset — audit every `TERRAIN_MAX_HEIGHT` import (grep shows `sim/missile.py`, `sim/aircraft.py`, `sim/enemy_air.py`, `sim/recon.py`, `sim/sam.py`).

## Feature: Seeded new-map presets (Open Sea / Archipelago / Narrow Strait / Fjord Coast)  _(effort: L)_

**What it is + real-world grounding:**

Four selectable battle maps, each a deterministic `HeightField` built from `np.random.default_rng([seed, 12])`, chosen on the setup screen. **Open Sea** — today's mostly-open layout (the baseline; little masking, a blue-water fight). **Archipelago** — many mid-ocean islands forming a maze that masks both sides' radar and forces sea-skimmers to thread channels (terrain LOS finally bites for sensors AND missiles). **Narrow Strait** — two land masses pinching the ocean into a chokepoint with flanking high ground, so a fleet must transit a kill-box and the player must watch one gap. **Fjord Coast** — a deeply indented enemy coast with tall walls (the one preset that wants real height shaping + possibly a higher `max_height`), creating dead ground where TELs/radars hide behind ridgelines and missiles must pop up to clear walls. Grounded in real geography (Aegean archipelago, Hormuz/Malacca straits, Norwegian fjords) and in the doctrine the game already models — terrain-masking is the missing tactical dimension; these presets exercise the radar-horizon + `terrain_blocks` physics that today's open ocean barely uses.

**Platform:**

N/A. Each preset is a field; the home-coast base cluster (base/SAM/Pantsir/Oniks/S-300 pads, the radar station) stays geometrically stable across presets (recommended — keeps armory/UX/tests stable), so the entities sit on consistent ground; what varies is the SEA, the ISLANDS, and the ENEMY-side approaches. (Open question 3 — confirm with integrator whether any preset relocates the home cluster.)

**Sensors (uses / detected by):**

This is the WHOLE POINT — presets make terrain-masking matter, for radar/SAR/ELINT AND for missiles, **both ways and honestly**. Because every sensor and missile already reads LOS through the active field's `height_scalar` (Feature 3), an Archipelago island between an enemy destroyer and the player radar BLOCKS detection in BOTH directions automatically (the enemy can't see the player's radar through it either, and the player's drone SAR is blocked the same way) — no per-preset sensor code, the `terrain_blocks` gate does it. Sea-skimming Oniks must now route around/through gaps (a missile's LOS-to-target and its ground-impact check both read the field), and a Fjord wall forces a pop-up. Radar-horizon physics (`radar_horizon_m`) interacts with the new high ground: a sensor on a Fjord ridge sees farther; a target in a fjord shadow is masked even within range. NON-NEGOTIABLE: no truth leak — the AI sees only what its radars pass through the SAME field; the masking is symmetric by construction (Feature 3's symmetry test guarantees it).

**AI brain (how the enemy commander uses or counters it):**

**No AI change for v1** (recommended scope). The enemy commander automatically copes with masking via its gated picture — islands/walls reduce what it sees and where its strikes can reach exactly as they do for the player, emergently. It does NOT yet route ingress through gaps or deliberately mask behind islands — that terrain-aware tactics layer is the **named highest-value follow-up** (call it out to the orchestrator), not part of this spec. v1's bar: the existing AI must remain *functional and not stuck* on every preset (e.g. it can still find a fire line to its targets) — verified by running the combat smoke gate on each preset.

**Player UX:**

A **MAP** row on the setup World page cycles OPEN SEA / ARCHIPELAGO / NARROW STRAIT / FJORD COAST; combined with the SEED, the map is fully deterministic and replayable. The chosen preset's terrain loads with the upgraded look (Feature 1) and the player's quality toggle (Feature 2). In battle the player experiences real dead ground, channels, and chokepoints — the tactical map (`game/tactical_map.py`) shows the new coastline (it samples the same field), so planning around masks is legible.

**UI needs:**

(1) A **MAP** row in `game/combat_setup.py` `_WORLD_ROWS` using the `enum` row kind introduced in Feature 2 (LEFT/RIGHT cycles the preset names), bound to a new `map_preset` CombatConfig field. (2) The setup screen's preview/labels should name the preset; an optional one-line flavor string per preset. (3) No new in-battle UI — the tactical map and 3D view already render whatever field is active.

**Game-model mapping (reuse vs add):**

REUSE the `HeightField` (Feature 3) — each preset is a `HeightField` constructed with preset-specific parameters (island sets, coast indentation, cliff/wall params, `max_height`) seeded by `np.random.default_rng([seed, 12])`. ADD a `world/generation.py::make_field(preset: int, seed: int) -> HeightField` factory (preset 0 = the DEFAULT field, byte-identical). ADD ONE CombatConfig field `map_preset: int = 0` + `CLAMP_MAP_PRESET = (0, 3)` + a `MAP_PRESET_NAMES` table + clamp_config wiring (LOCKED schema — sign-off). `world/combat.py` calls `make_field(config.map_preset, config.seed)` and threads it everywhere (the Feature-3 plumbing). The renderers (`world/terrain.py` `FEATURES`/`ISLANDS`, `world/ocean.py`) read the active field's islands/coast extents — so `Terrain` must take the field (its `FEATURES` rects derive from the field's island list + coast bands) instead of importing module `ISLANDS` directly (a Feature-3-adjacent change: make `Terrain(field)` and `world/ocean.py` near-shore weights field-derived). Lane/ship/aircraft spawns (`LANES`/`SHIP_SPAWNS`/`AIRCRAFT_SPAWNS`) may need per-preset variants so ships don't spawn inside an island — gate behind the field (a preset that adds islands must dodge them, mirroring the existing ">= 12 km from ISLANDS" lane comment).

**Implementation sketch + test contracts:**

Files: `world/generation.py` (`make_field` factory + the four preset parameterizations of `HeightField`, all seeded `[seed, 12]`), `world/combat.py` (build via `make_field`, thread field + field-derived spawns), `world/terrain.py` (`Terrain(field)` — `FEATURES`/`ISLANDS`/`h_ref` from the field), `world/ocean.py` (field-derived near-shore weights), `world/combat_config.py` (`map_preset` + clamp + names — sign-off), `game/combat_setup.py` (MAP enum row). Probes: `tools/probe_preset_masking.py` per preset. TEST CONTRACTS: (a) **DEFAULT preset byte-identical** — `make_field(0, 1337)` produces a field bit-identical to today's default over the fixed grid (preset 0 must NOT regress — the gate). (b) **determinism** — `make_field(p, s)` twice gives identical heights for all p, s; different seeds give different islands (a content check), same seed+preset replays exactly. (c) **masking bites** — `tools/probe_preset_masking.py` asserts that on Archipelago/Strait/Fjord there EXIST sensor/target pairs where `terrain_blocks` is True (it's actually used), and that a known fjord-shadow target is masked from a known sensor; on Open Sea masking is rare (baseline). (d) **symmetry/honesty** — on each preset, enemy and player `height_fn` are the same field instance (reuse Feature 3's test); a target hidden from the player by terrain is also hidden from the enemy by the same geometry (no asymmetric truth). (e) **`max_height` respected** — every preset stays under its own `field.max_height` (assert `field.height(grid).max() < field.max_height`), and Fjord's taller `max_height` still satisfies the flyer-skip optimization. (f) **AI not stuck** — run `tools/smoke_combat.py` (or a per-preset smoke) on each preset to exit 0 (the AI finds fire lines, the battle resolves). (g) **spawns valid** — no ship/aircraft spawns on land for any preset (assert `field.height_scalar` <= 0 at every spawn point). (h) the setup MAP row: `tests/test_combat_setup.py` cycles `map_preset` within clamp and START emits it.

**Counters / balance:**

Presets ARE the balance variety: Open Sea favors blue-water sensor/range duels (today's balance, frozen by preset 0); Archipelago/Strait reward terrain-masked sneaking and chokepoint ambushes (the player can mask launches behind islands — but so can the enemy mask ingress, symmetric); Fjord rewards dead-ground hiding and punishes flat sea-skim (missiles must pop up over walls, exposing them to SM-2 — a real trade). Each preset must be WINNABLE and LOSABLE (per the project's "the enemy can win" mandate) — tune island density/strait width/fjord wall height so neither side is trivially safe; verify with the per-preset smoke + a quick playtest hook. Physics-not-dice + fog held throughout: every masked detection/miss emerges from the shared field geometry, never a flag.

**Risks:**

(1) Determinism drift — a preset that uses wall-clock or an unseeded RNG breaks replay; ALL randomness must be `np.random.default_rng([seed, 12])` (test b). (2) Preset 0 must stay byte-identical — easy to regress while parameterizing; gate (a) is mandatory. (3) Spawns-on-land — adding islands without dodging lanes spawns a ship inside a hill; gate (g). (4) AI stuck on a pinched map — a strait that fully walls off the enemy's fire line softlocks the battle; gate (f) + tune geometry. (5) `Terrain(field)`/`world/ocean.py` field-derived rects touch the (carefully perf-tuned) LOD/ring streaming — keep the tile-budget + seam invariants from `world/terrain.py` (don't regress the frame-time gate). (6) Scope: keep presets static (chosen at setup); dynamic weather/tide is future work. (7) Renderer must show the SAME field the sim masks with — if `Terrain` ever falls back to module `ISLANDS` while the sim uses a preset field, the player sees a coastline that doesn't match LOS (a fog-honesty *perception* bug) — assert the renderer's field is the world's field.
